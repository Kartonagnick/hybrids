[![S]][M] Кодировка и EOL v0.0.1
================================
Рекомендации от Алисы.  

Суть рекоментадиции: поскольку, студийные скрипты (`props/vcxproj/csproj/targets`) 
используются в основном именно Visual Studio, под Windows, то Алиса посчитала нужным 
явно указать рекомендацию использовать именно виндузятный стиль.  

Однако нужно понимать, что окончание строк `LF` для студийных скриптов 
обусловленно потребностью выполнять сборку под Linux.  

В сценариях сборки могут быть всякие `remote post build`, и прочие подобные шаги.  
В прошлых версиях Visual Studio был такой баг: если студиный скрипт имел окончание строк `CRLF`, 
то сценарий, который запускался уже на стороне Linux, тоже имел окончание строк `CRLF`, 
что приводило к ошибкам запуска на Linux.  

В то же время, если для студийных скриптов сделать окончание строк `LF`, 
тогда сборка работает и под Linux, и под Windows.  
То есть, получаем `золотой стандарт` - кроссплатформенный вариант, который не создает проблем.  

После того, как я объяснил этот момент Алисе, она скорректировала своё итоговое мнение:  
- если нужен `remove build` под `Linux`, тогда лучше использовать `LF`  
- в противном случае, лучше использовать `CRLF`  

Следующая таблица: рекомендация для случая, когда `remove build` не требуется.  

| Расширение           | Кодировка                       | EOL                  | Примечание                                                                                         |
| -------------------- | ------------------------------- | -------------------- | -------------------------------------------------------------------------------------------------- |
| py                   | UTF-8                           | LF                   | Кросс-платформа. BOM не требуется.                                                                 |
| ps1                  | UTF-8 + BOM                     | CRLF                 | Без BOM возможны проблемы с отображением кириллицы в старых версиях PowerShell.                    |
| bat                  | OEM 866                         | CRLF                 | LF может вызвать ошибки выполнения.                                                                |
| vbs                  | UTF-16 LE + BOM (рекомендуется) | CRLF                 | UTF-16 гарантирует поддержку всех символов. Windows‑1251 ограничен кириллицей и латиницей.         |
|                      | или Windows-1251 (ANSI)         |                      |                                                                                                    |
| wsh                  | UTF-16 LE + BOM (рекомендуется) | CRLF                 | UTF-16 гарантирует поддержку всех символов. Windows‑1251 ограничен кириллицей и латиницей.         |
|                      | или Windows-1251 (ANSI)         |                      |                                                                                                    |
| bash                 | UTF-8                           | LF                   | CRLF в первой строке (`#!/bin/bash`) вызывает ошибку. BOM не допускается.                          |
| sh                   | UTF-8                           | LF                   | Аналогично bash. CRLF в шебанге приводит к ошибке. BOM не допускается.                             |
| cmake/CMakeLists.txt | UTF-8                           | LF                   | BOM может вызвать предупреждения CMake.                                                            |
| sln                  | UTF-8 + BOM                     | CRLF                 | Стандарт для Visual Studio. BOM обязателен для корректного отображения кириллицы.                  |
| props                | UTF-8 + BOM                     | CRLF (рекомендуется) | При редактировании на Windows и сборке на Linux BOM и CRLF помогают избежать проблем с кодировкой. |
| vcxproj              | UTF-8 + BOM                     | CRLF (рекомендуется) | Аналогично props. Visual Studio по умолчанию использует CRLF.                                      |
| csproj               | UTF-8 + BOM                     | CRLF (рекомендуется) | Аналогично props.                                                                                  |
| targets              | UTF-8 + BOM                     | CRLF (рекомендуется) | Аналогично props.                                                                                  |
| cpp/hpp              | UTF-8 (рекомендуется)           | LF                   | UTF-8 без BOM предпочтительнее для кросс‑платформенности. BOM допустим, но может мешать            |
|                      | или UTF-8 + BOM                 |                      | инструментам Unix.                                                                                 |
| c/h                  | UTF-8 (рекомендуется)           | LF                   | Аналогично cpp/hpp.                                                                                |
|                      | или UTF-8 + BOM                 |                      |                                                                                                    |
| cs                   | UTF-8 (рекомендуется)           | LF                   | UTF-8 без BOM — стандарт для .NET. BOM допустимо, но не обязательно.                               |
|                      | или UTF-8 + BOM                 |                      |                                                                                                    |
