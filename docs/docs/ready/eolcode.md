[![P]][M] eolcode v0.0.1
========================
Гибрид предназначен для сканирования репозитория,  
и выявления нарушений кодировки и EOL файлов  
<br/>

Что проверяется
---------------
Гибрид рекурсивно обходит репозиторий и проверяет файлы, которые считает текстовыми:

- файл должен быть валидным UTF-8;
- окончание строк должно соответствовать типу файла;
- файлы неизвестного типа дополнительно помечаются в выводе как `[u]`.

Гибрид только сообщает о найденных нарушениях.  
Файлы не исправляются и не перезаписываются.  
<br/>


Обозначения вывода
------------------

|          метка           |                                   значение                                   |
|:------------------------:|:-----------------------------------------------------------------------------|
| `[u]`                    | unknown: имя файла не попало в список известных текстовых или бинарных масок |
| `[WARNING] invalid utf8` | файл считается текстовым, но проверка UTF-8 не пройдена                      |
| `[WARNING] invalid eol`  | файл считается текстовым, но EOL отличается от ожидаемого                    |

Метка `[u]` не означает, что файл является UTF-8.  
После такой метки гибрид всё равно решает по эвристике, считать файл текстовым или бинарным.  
<br/>


Известные типы файлов
---------------------
Файл считается известным текстовым, если его имя совпало с одной из масок  
без учёта регистра:

```text
*.cpp; *.hpp; *.h; *.c; *.cxx; *.hxx
*.bat; *.cmd; *.vbs; *.wsf; *.sh; *.bash; *.txt; *.md; *.rs
*.cmake; *.sln; *.vcproj; *.vcxproj; *.csproj; *.props
*.vcxproj.user; *.vcxproj.filters; *.rc; *.natvis; *.def
*.html; *.httml; *.graphml; *.cs; *.css; *.json; *.xml; *.yml; *.yaml; *.svg
*.asm; *.swift; *.js; *.kt; *.go; *.lua; *.java; *.php; *.py; *.dart; *.razor; *.jnfo; *.sql
makefile; CHANGELOG; CREDITS; LICENSE; .gitmodules; .gitignore; project.root
```

Файл считается известным бинарным, если его имя совпало с одной из масок  
без учёта регистра:

```text
*.lib; *.dll; *.exe; *.pdb; *.mod; *.a; *.so; *.o
*.jpg; *.png; *.bmp; *.gif; *.mp4; *.avi; *.ttf
*.tar.gz; *.7z; *.zip; *.tlb; *.dat
```

Если имя файла не совпало ни с текстовыми, ни с бинарными масками, выводится `[u]`,  
а текстовость определяется эвристически по содержимому файла.  
<br/>


Правила EOL
-----------

| тип файла                                                                          | ожидаемый EOL |
|:----------------------------------------------------------------------------------:|:-------------:|
| `bat`, `cmd`, `vbs`, `wsf`, `sln`, `sln.all`, `sln.bld`, `user`, `vcxproj.filters` | `CRLF`        |
| `sh`, `bash`                                                                       | `LF`          |
| остальные текстовые файлы                                                          | `LF`          |

Для пустого файла фактический EOL считается `CRLF`.  
Тип для выбора EOL определяется по суффиксу имени файла.  
<br/>


Исключения
----------
При обходе репозитория пропускаются каталоги:

```text
_*
.git
.vs
temp
output
debug
release
boost
```

Также пропускаются файлы с именем, начинающимся на `_`.  
<br/>


Пример использования
--------------------
Работает гибрид полностью в автоматическом режиме.  
1. Копируем файл гибрида  `ready/eolcode.bat`  в стеш бананового проекта.  
2. Запускаем гибрид на выполнение.  
3. Ожидаемый результат: покажет все нарушения.  
<br/>


Управляющие параметры
---------------------

|     переменная     |                 назначение                 |
|:------------------:|:------------------------------------------:|
| eDEBUG             | вкл/выкл отладочный вывод                  |
| eDIR_WORK          | путь к репозиторию или стешу               |
| eLOG.PATH          | путь к файлу лога                          |
| eLOG.FLUSH         | не используется                            |
| eLOG.APPEND        | добавлять/перезаписывать лог               |
| eLOG.SYSTEM_LOCALE | `ON` - лог в системной локали, иначе UTF-8 |
| eSILENCE           | отключить вывод в консоль                  |
| eINDENT            | дополнительный отступ вывода               |

```bat
set "eDIR_WORK=D:\repo\Bolid\_stash\parametric"
set "eLOG.PATH=D:\repo\Bolid\eolcode.log"
set "eLOG.SYSTEM_LOCALE=ON"
set "eLOG.APPEND=ON"
set "eDEBUG=ON"
```

Для PowerShell переменные с точкой в имени нужно задавать через `Set-Item`:

```powershell
Set-Item -Path Env:\eDIR_WORK -Value 'D:\repo\Bolid\_stash\parametric'
Set-Item -Path Env:\eLOG.PATH -Value 'D:\repo\Bolid\eolcode.log'
Set-Item -Path Env:\eLOG.SYSTEM_LOCALE -Value 'ON'
Set-Item -Path Env:\eLOG.APPEND -Value 'ON'
Set-Item -Path Env:\eDEBUG -Value 'ON'
.\eolcode.bat
```
<br/>


Логирование
-----------
По умолчанию лог пишется в файл `eolcode.log` в текущем каталоге запуска.  
Если `eLOG.APPEND` не включён, старый лог перезаписывается.  

Рекомендуется указывать `eLOG.PATH` вне проверяемого репозитория.  
Если лог находится внутри сканируемого каталога, он также может попасть в проверку.  
<br/>


Ограничения
-----------

- Проверка UTF-8 выполняется по первым `10000` байтам файла.
- Определение EOL выполняется по первому найденному переводу строки в первых `10000` символах.
- Смешанные окончания строк внутри одного файла могут быть не обнаружены.
- Для неизвестных имён файлов текстовость определяется эвристически.
